# 排错

## 先做这两件事

**1）看日志**：`%LOCALAPPDATA%\Liwangtong\campus_login.log`（`Win+R` 粘这个路径就能打开目录）

日志是按标签分的，搜这几个前缀最快：

| 标签 | 内容 |
|------|------|
| `[DAEMON]` | 守护循环：状态检测、掉线判定、重连过程 |
| `[TRAY]` | 托盘图标创建/退出、菜单动作、拉起界面的过程 |
| `[POPUP]` | 主界面进程 |
| `[INIT]` | 账号密码配置窗口 |
| `[STATUS]` | `chkstatus` 请求失败、状态解析失败 |
| `[CRASH]` | 没被接住的异常（带栈） |
| `[MUTEX]` / `[PROC]` | 单例锁、进程启停 |
| `[SECURITY]` / `[MIGRATE]` | 明文密码迁移到凭据管理器的记录 |

注意日志超过 512KB 会被截到最后 200 行，所以别等到复现不了才想起看日志。

**2）跑自检**，它会一次性打印账号、凭据是否已存储、自启状态、守护是否在跑、认证状态，并自动把结果复制到剪贴板：

```
set PYTHONIOENCODING=utf-8
python src\campus_login.py diagnostic
```

没有源码环境的话，直接在 PowerShell 里试打包版的 `diagnostic`：因为程序名带 🍐，中文终端会 `UnicodeEncodeError` 崩掉，这是已知问题，不是你机器的毛病 —— 那就用上面的源码方式，或者退一步看界面和日志。

（不想装 Python 又想要一份状态：`梨网通.exe autostart` 和 `梨网通.exe quit` 这几条不含 emoji 的命令在终端里是能正常打印的。）

## 登录失败 / 一直显示未连接

按这个顺序排，基本能覆盖：

1. **浏览器打开认证网关看看**（代码里的 `BASE_URL`，默认 `http://10.255.0.19`）。打不开说明根本没连到校园网内网，或者你学校/校区的网关地址不一样 —— 那要改 `src/campus_login.py` 的 `BASE_URL` 重新打包。
2. **手动登录一次看看能不能上**。用学校给的方式（浏览器 / 官方客户端）能上、这个程序上不了，才是程序的问题。
3. **账号后缀对不对**：联通 `@unicom`、电信 `@aust`、移动 `@cmcc`。学校给的是哪个就选哪个，选错的表现就是「密码明明对，一直登录失败」。
4. **凭据是不是旧的**：改过校园网密码的话，要在程序里重新保存一次（托盘 → 修改账号密码），或者直接去凭据管理器删掉 `campus_login` 那条再重填。
5. **日志里 `[STATUS] chkstatus 请求失败`** 说明能发请求但拿不到状态：常见于网关地址不通、或者认证系统改版了。
6. **登录请求返回的文本程序认不出**：不同 Dr.COM 版本回的内容不一样（`login_ok` / `认证成功` / `UID=...ac0=` / `result:1`），需要抓一次返回内容对着改判断条件。这个只能改代码。

## 开机自启了，但开机没连上

- 先分清两件事：**开机认证一次是无条件执行**的，「后台守护」开关只管掉线之后要不要持续重连。守护关着也应该能开机连上。
- 检查托盘图标在不在。开机后如果托盘没有图标，说明自启没生效：`梨网通.exe autostart` 会打印当前状态，正确应该是 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 里有 `liwangtong` 指向 `...daemon`。
- **别用管理员身份运行安装/程序**。它声明的是 `PrivilegesRequired=lowest`，用管理员跑一次，数据目录和自启项就会写到另一个账户下面，看起来就像「设置全没了」。
- 网卡初始化慢的机器（尤其有线口 + DHCP）会赶不上第一次认证，守护循环会在 30 秒后重试，等一分钟再看。
- 快速启动（Fast Startup）会让「开机」接近于唤醒，网络栈状态奇怪。遇到只在开机时不连、重启就正常的情况，把控制面板里的「启用快速启动」关掉再试。

## 界面打不开 / 闪一下就没了

- 托盘左键是「显示已存在的界面」，不是「启动新界面」。如果 daemon 已经退出（托盘图标都没了），左键自然什么都没发生 → 双击 `梨网通.exe`（无参数）会重新拉起 daemon + 界面。
- **闪一下就退**，基本都是 `runtime.json` 里 `app_quit` 残留为 `true`：上次退出时进程被强杀（任务管理器结束、断电、注销），标记没清。处理：双击 exe 打开程序（它启动时会清这个标记），或者删掉 `%LOCALAPPDATA%\Liwangtong\runtime.json` 再来一次。
- 如果是配置窗口「只闪一下」：说明它保存后试图重启守护、抢不到 `MUTEX_DAEMON` 自己退了 —— 关掉已有的守护进程再打开配置窗口。
- 界面完全没出来，日志里有 `[TRAY][FATAL]` 或 `[CRASH]`：把这几行贴到 Issue 里。

## 托盘图标异常

- **图标不见了但网还连着**：daemon 进程被杀了（清理软件、任务管理器）。任务管理器里确认有没有 `梨网通.exe`；没有就双击 exe 重启。
- **图标颜色对不上**：粉色 = 已连接，灰色 = 未连接，淡紫粉 = 连接中。颜色只反映 `runtime.json` 里的状态，如果守护没在跑（托盘没了、只剩 popup），状态就不会更新。
- **右键菜单点了没反应**：pystray 的菜单回调跑在它自己的线程里，如果那时 daemon 工作线程正卡在 `chkstatus` 的超时等待（默认 8 秒），会有明显延迟。反复出现就看日志里有没有大量 `[STATUS]` 失败。

## 掉线了不自动重连

1. 托盘右键看「后台守护」有没有勾 —— 关着就不会重连。
2. 你是不是**手动点过「注销」**。手动注销会写 `manual_logout` 标记，守护会尊重你的操作、不再自动登录，直到你重新点「连接」或重启程序。这是设计如此（不然手动注销完又被自动连回去，很难受）。
3. 刚登录成功 15 秒内（`grace_period`）判掉线会被忽略，避免认证还没落地就误判。
4. 重连节奏：每 30 秒一轮，每轮最多试 3 次、退避 `2^n` 秒，所以最坏情况要等半分钟以上才恢复，不是卡死。
5. 想改这几个参数：`config.json` 里的 `daemon_interval` / `retry_max` / `retry_backoff` / `grace_period`（默认值见 `DEFAULTS`）。

## 凭据相关

- **`config.json` 里没有密码**是正常的，密码在 Windows 凭据管理器里（控制面板 → 用户账户 → 凭据管理器 → Windows 凭据 → `campus_login`）。
- 从很老的版本升上来、以前配置里存过明文密码的，程序会自动把它迁进凭据管理器并从 `config.json` 删掉，日志有 `[MIGRATE]` / `[SECURITY]` 记录。
- 换 Windows 账户 / 换机器，凭据是拿不过去的（凭据按当前用户存），得重新输一次密码。
- 彻底清掉：凭据管理器里删 `campus_login` 那条，再删 `%LOCALAPPDATA%\Liwangtong\`。

## 卸载残留

卸载完还剩 `梨网通.exe` 或 `_internal\` 目录 = 退出时进程还锁着文件。

- 正常流程卸载器会先跑 `梨网通.exe quit` 等进程真退出（最多 15 秒）。
- 手动处理：托盘右键「退出」→ 任务管理器确认没有 `梨网通.exe` → 再卸载。还不行就重启一次再卸载。
- `%LOCALAPPDATA%\Liwangtong\`（配置、日志、凭据辅助文件）卸载**故意不清**，方便你重装；不想留手工删。

## 杀软 / SmartScreen

- SmartScreen 提示「未知发布者」：没有代码签名，正常。点「更多信息 → 仍要运行」。
- 被杀软直接删掉 exe：PyInstaller 产物的常见误报。先 VirusTotal 扫一遍确认，再把安装目录加白名单；自己打包的话把 `upx` 关掉（仓库里的 spec 已经关了）。

## 彻底重置

```powershell
& "$env:LOCALAPPDATA\PearTech\Liwangtong\梨网通.exe" quit
Remove-Item "$env:LOCALAPPDATA\Liwangtong" -Recurse -Force
# 凭据管理器里删掉 campus_login 那一条（控制面板 → 用户账户 → 凭据管理器）
```

## 提 Issue 时带上这些

- Windows 版本（`winver` 里那串）、程序版本（安装包文件名或「应用和功能」里的版本）
- 运营商（联通 / 电信 / 移动）
- 现象和期望：什么时候开始、每次必现还是偶发
- 自检报告（`python src\campus_login.py diagnostic` 的输出，跑完自动在剪贴板里，学号可以打码）
- 日志里相关的十几行，别只截一张图
- `[CRASH]` 那几行如果有栈就完整贴出来

「不能登录，怎么办」这种我确实没法判断。安全类问题（凭据泄露、代码执行）不要开公开 Issue，见 [SECURITY.md](../SECURITY.md)。
